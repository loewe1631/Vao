# Human-led, built with AI

[中文](AI_DEVELOPMENT.md) · [Project home](README.md)

An open account of how a voice-input product is made.

Vao started with concrete problems a human encountered while using voice-input tools day to day. Multiple AI agents help analyze different tools and their user experience. Continued use and feedback turn those needs into an app that people can install and use.

## What we mean by end-to-end AI creation

AI participates throughout product research, solution design, code implementation, engineering checks, website creation, promotional materials and routine operations. A human proposes needs, chooses approaches, performs hands-on acceptance testing and decides which improvements to release.

> **A human decides what to make. AI agents work together to build it.**

## Who participates, and how

| Area | Participants or tools | Work |
| --- | --- | --- |
| Product direction and acceptance | Human | Propose needs, assess the experience, report problems and decide releases. |
| Research and planning | Multiple AI agents | Combine research into voice-input tools with everyday usage experience to develop design proposals. |
| Development and engineering checks | Codex, DSH, opencode and other agent tools | Implement features, investigate difficult issues, review code, test and write technical documentation. |
| Website creation | AI agent collaboration | Page design, frontend implementation and copy editing. |
| Routine maintenance | Grok Bot | Routine website maintenance, GitHub activity monitoring, and issue and pull-request summaries. |
| Promotion and operations | Grok Bot | Social platform articles, comments, publishing and routine account management. |
| Promotional videos | Manus + Seedance 2.5 | Produce product promotional videos. |

**Participating models:** Models used in the project include GPT-6.1 Sol, GPT6-Astra, Grok4.7 and Gemini3.8 flash, among others.

## From a need to the next improvement

Real needs → AI analysis and implementation → Engineering checks → Human hands-on testing → Iteration and release

Recording, shortcuts, cross-app insertion and vocabulary migration have been refined through continued use and problem reports. Each release should explain what changed, what was checked and which scenarios remain unverified.

## How to participate

Human-written and AI-assisted contributions are welcome. Make each change understandable and reproducible for other contributors:

- Explain the concrete problem and the behavior being changed.
- Describe how to reproduce or validate it and the actual results.
- State what remains unverified.

A human makes final decisions on product direction, accepting contributions and publishing releases. Third-party code, assets and dependencies retain their source and license requirements. See [contributing](CONTRIBUTING.md), [governance](GOVERNANCE.md) and [provenance](PROVENANCE.md).

This document records project participation. For specific features, compatibility and validation status, refer to the corresponding source revision and [release notes](RELEASE_NOTES.md).
