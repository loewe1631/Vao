# Governance

The repository owner maintains product scope, reviews contributions and controls releases. Additional maintainers are appointed explicitly through repository access settings. Opening a pull request or passing an automated check does not grant release access.

AI agents participate in analysis, implementation, engineering checks and routine maintenance. A human makes final decisions on product scope, accepting contributions and publishing releases. See [AI collaboration](AI_DEVELOPMENT.en.md) ([中文](AI_DEVELOPMENT.md)) for participating tools, models and responsibilities.

Discuss substantial session, privacy, persistence or platform-contract changes in an issue or RFC first. Accepted architecture decisions include alternatives, migration and validation. Coordinate overlapping implementation through the issue or pull request.

User data, learned preferences, cancellation and delivery changes need focused review. Releases identify source revision, version and build, include checksums and licenses, and state limitations. Distinguish synthetic checks from model, installation and real desktop acceptance.

Normal collaboration uses issues and pull requests. Follow [SECURITY.md](SECURITY.md) for sensitive reports. No response-time or availability commitment is made. Governance changes are reviewed like other project changes.
